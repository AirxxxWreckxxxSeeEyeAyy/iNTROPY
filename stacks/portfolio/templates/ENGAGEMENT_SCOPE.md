# Lab exercise scope — COPY AND FILL

This is a technical lab planning template, not a completed authorization or a legal contract.

| Item | Required detail |
| --- | --- |
| Lab owner / operator | Names or private record references |
| Objective | One measurable outcome |
| Start/end window | Date, time, timezone |
| Exact targets | Owned instance identifiers and allowlisted addresses |
| Synthetic accounts/data | Roles and fixture descriptions; no credentials |
| Permitted activity | Specific tests/simulations and reasonable request limits |
| Excluded activity | All other targets; destructive actions; unrelated users/data |
| Isolation | Network path and how unintended exposure is prevented |
| Monitoring | Logs, clocks, collection, alert/query owner |
| Stop conditions | Loss of scope, unexpected data, instability, or loss of recovery access |
| Stop/recovery owner | Who can stop the test and restore the fixture |
| Backup/reset | Known-good state and how to restore it |
| Evidence handling | Private originals, redaction, retention, public artifacts |
| Cleanup | Test accounts/files, sessions, services, and temporary access |
| Acceptance tests | IDs from TEST_PLAN.md |

Before executing, confirm that the actual target and configuration match this scope. For work on another party's systems, establish their explicit authorization and agreed rules before testing.
